# 界面与视听表现

## 界面与反馈

**章节状态：信息职责、餐车状态、烹饪圆环、暂停详情与纸张艺术方向已确认；其余具体布局待定。**

### 信息层级

1. 餐车位置、六区占位、当前目标、危险预警和 Boss 攻击是最高层级。
2. 餐车耐久、食客胃口、强化门数值与稀有度、特殊三选一是第二层级。
3. 食材等级、普通强化累计和局内统计是第三层级。

### 关键反馈

- 食客胃口以“逐渐吃饱”的方向表达，避免把满足误读为传统伤害。
- 餐车耐久固定在屏幕下方、靠近厨师与餐车的视觉焦点，常驻显示当前值与最大值；存在临时护盾时在同一区域追加护盾点数，护盾耗尽后隐藏。
- 厨师与餐车整体头顶使用固定宽度的耐久纸条，只按当前耐久与最大耐久的比例改变填充长度。临时护盾存在时追加蓝色描边和护盾点数徽记；最大耐久提高时短暂显示实际增加点数，不随上限成长扩大纸条宽度。
- 底部耐久区上方按已取得食材逐个显示圆形烹饪进度。每种食材独立顺时针转圈、固定显示一位小数的剩余秒数和当前等级；土豆、法棍与蘑菇使用简洁纸艺图标，缺少专用图标的后续食材回退为名称首字。衍生攻击不另占圆环。
- 前进阶段和Boss阶段提供正式暂停入口；暂停后冻结局内时间、输入与烹饪进度，并显示当前/最大耐久、护盾、全部普通强化累计，以及每种食材的有效满足值、烹饪间隔、范围、持续、份数、命中和特殊特性。特殊三选一、结算、失败和Debug界面优先于普通暂停。
- 不常驻显示黑色食材信息条；食材精确详情进入暂停页，战斗中只保留圆形烹饪节奏和取得反馈。
- 食客被满足时播放打嗝、满足表情、点赞或抱空盘离场；不倒地、不爆炸。
- 普通门必须在进入判定前显示强化对象、实时数值和稀有度；每侧头顶使用纸条血条与数字显示随初始百分位提高的公开基础血量，使高稀有门的风险同步可见。
- 普通门左右门板和食客奖励门使用当前稀有度颜色；受击升值跨档时门板立即换色，不能只更新文字标签。
- 普通门隐藏升值血量不显示；基础层击破后的继续命中只通过奖励数值、稀有度和面板反馈表现。食客奖励门没有基础层，其全部升值血量同样隐藏，只通过奖励数值、稀有度和面板反馈表现。
- 攻击普通门时只让实际命中的一侧短促亮闪，并同步强调变化中的公开基础血量或奖励数值。
- 食客受到投喂时使用短促亮闪和轻微缩放，反馈“正在被满足”而不是受伤。
- 普通食客头顶使用纸条血条与数字显示当前胃口，色条继承其奖励稀有度；击败后生成的单段奖励门只显示强化名称、实际数值和稀有度，不显示升值血量。
- 未命中的食材在寿命耗尽或越界后用`0.2s`快速缩小并淡出；命中次数耗尽仍立即回收，不拖延命中反馈。
- 新食材出现时先展示清楚轮廓，再开始自动攻击。
- 特殊强化必须能从轮廓、数量、轨迹、范围、持续区域或攻击节奏中看出变化。
- 作用范围的实际判定继续按完整强化倍率增长，但普通食材和巨型法棍的实体模型最多显示为基础范围的`1.5`倍，巨型法棍实体宽度不超过六区道路。超过实体上限的有效范围改用无填充、低透明细轮廓表达；范围轮廓不得压过食客、强化门和Boss危险预警。
- Boss 危险预警不能与料理特效共用主要形状，只依赖颜色的预警不合格。

## 视觉方向

**章节状态：纸张艺术与固定斜俯 3D 舞台已确认；正式样板与资产规格待定。**

- 画面比例为 `9:16`，采用固定斜俯透视的三维纸艺道路舞台；长竖屏增加前方视野，不缩小横向玩法区域。
- 当前实现在固定相机中同时呈现四段有效道路，并让食客与门从远端进入；前后额外路块仅用于无缝循环。
- 道路变长只增加可见距离，不改变食客与门的接近速度；远端对象按新增路程和各自原速度提前排程，并继续使用原事件时刻对应的基准数值。
- 相机采用近端道路宽、远端明显收束的固定透视；Mobile渲染使用廉价深度雾遮蔽远端生成区域，不启用体积雾。
- 实机核心视觉统一采用原创纸张艺术，不再并用其他主体美术风格。
- 材质语言以复古印刷拼贴、黑白半调网点剪贴、粗糙轮廓、错位强调色描边和可见印刷颗粒为核心。
- 道路平铺在三维 `X/Z` 平面，餐车、食客、食材、强化门和环境主体使用竖立纸偶或薄纸构件；三维节点直接持有移动与表现，不保留不可见二维映射层。
- 中央马路、左右路沿与左右人行道使用独立贴图和独立3D构件；路沿与人行道略高于马路，形成可见但克制的纸层高度差，不改变六区与碰撞判定。
- 六区、连续横移、目标和命中仍按道路平面规则计算；高度只服务视觉，不成为新的玩法变量。
- 相机、灯光、道路、纸偶、标签、阴影与预警以 Godot 场景节点装配，必须能在编辑器中预览和调整，不把主要节点树完全改为运行时代码生成。
- 街景图集裁剪由每个`Sprite3D`节点自己的区域矩形保存；裁剪、统一大小、非等比缩放和摆放都应能在`world_background_3d.tscn`中直接手调。
- 角色与食材保持夸张、清楚的轮廓；食客表情可以紧张、急切或怪诞，但整体情绪仍遵循荒诞温暖，不转向写实恐怖。
- 正式色板仍待样板确认；料理、特殊强化和危险预警必须使用比环境更醒目的强调色，并保持形状层面的独立辨识。
- 参考风格只拆解媒介、线条和气质，不复刻现有游戏的角色、怪物、界面或标志。
- UI 与纸偶图片不烘焙实际文字和数值；固定屏幕信息在独立HUD场景中使用可编辑`Control`节点装配，胃口与门信息使用附着于三维物件的文字及纸条节点。

## 声音方向

- 自动上菜使用短促、节奏明确的切菜、甩锅、酥脆碰撞和蒸汽声，不使用枪械拟真音效。
- 食客满足、餐车受击、普通强化、特殊强化、精英和 Boss 预警分别使用不同音色。
- 连续高攻速食材需要合并或限频音效，避免后期形成持续噪声。
