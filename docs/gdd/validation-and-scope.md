# 验证与制作边界

## 原型验证轮廓

**章节状态：验证方向已确认；量化成功阈值待定。**

首轮原型需要回答：

1. 玩家能否理解连续横移与六个逻辑区域的关系？
2. 约 50 次普通强化是否产生持续成长，而不是选择疲劳？
3. 数值无上限叠加是否在八分钟内导致攻速、范围、移动或画面彻底失去可读性？
4. 普通食客通常占两区时，绕行与主动投喂是否都具有价值？
5. 六只精英能否形成节奏节点，而不是重复的静止胃口墙？
6. 混合随机特殊池能否同时支持获得新食材、加量和进化，不产生无效三选一？
7. 中途 Boss 是否形成有效换气，并能在胜利后让新强化继续发挥？
8. 最终 Boss 是否能检查完整构筑，而不会因停止前进变成另一款游戏？
9. 剩余胃口转化为餐车损失时，玩家能否理解失败原因并调整？
10. 料理、食客、强化门和 Boss 预警在终局高密度画面中是否仍可辨认？

待记录数据：门选择、稀有度分布、普通强化累计、特殊奖励、食材数量、精英耗时、Boss 受击来源、餐车耐久变化、失败阶段和总时长。具体成功阈值见[开放问题](open-questions.md#验证)。

## 制作边界

- GDD 只定义玩法与表现轮廓，不定义 Godot 节点、脚本、资源路径或数据格式。
- 当前具体数值包括用户确认的餐车耐久、首发食材基线、当前竖切片胃口曲线、可攻击门公式与普通强化区间；未确认的正式概率、八分钟数值与技能不得补造。
- 正式实现应建立本作独立数据源。
- 正式名称、完整内容表、商业化、排行榜、其他厨师和更多章节均不在当前轮廓确认范围内。
