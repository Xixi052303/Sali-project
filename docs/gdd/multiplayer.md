# 局域网多人规则

**章节状态：已确认首轮实现规格；运行联调与真机验收仍是制作验证项。**

## 范围与会话

- 保留单人快捷模式；新增 Android 与 Windows 编辑器/调试运行之间的同局域网合作。
- 一局支持 1～4 人。房主固定为 P1，客户端按加入顺序取得 P2～P4；房间阶段离开后空位可重新分配。
- 联机入口支持创建房间、自动发现房间和手输房主 IPv4。发现使用 UDP `28961`，游戏连接使用 ENet `28960`；房间广播每秒一次，超过 3 秒未收到即从列表移除。
- 房间广播与握手携带协议版本、六本运行工作簿指纹、房间状态和人数。版本/数据不一致、房间已满或已开局时拒绝加入；广播不可用时手输 IP 仍可用。
- 联机房间页固定显示 P1～P4 四个槽位，空位明确显示为“空位”；只有房主可以开始，成员离开后只在房间阶段重新分配空槽。
- 房主可在 1～4 人时开始；开始后锁定成员和人数，不允许中途加入。客户端断线立即离队，敌人倍率保持开局时锁定值；房主断线时所有客户端回到联机入口。
- 胜利或失败后房主让全员重新加载干净单局并回到原房间，连接与 P 位保留。暂不支持互联网匹配、专用服务器、密码、聊天、踢人、准备、中途加入、断线重连、房主迁移或跨版本联机。

## 权威与同步

- `NetworkSession` 是 Autoload，只持有房间、ENet、发现、输入和网络事件，不持有局内实体。
- 房主权威管理时间轴、随机流、敌人和 Boss、门血量、投射物命中、耐久、死亡/复活、暂停、特殊选择和结算。`RunState`、`UpgradeData` 等 Resource 不直接序列化，使用稳定 ID、数值字段和快照。
- 共享随机流决定普通门、奖励门、敌人和时间轴；每个玩家的开局食材与特殊三选一按槽位派生独立候选。敌人目标从存活玩家中均匀随机选择。
- 客户端最多 30Hz 发送带序号的移动目标；房主以 20Hz 广播玩家、敌人、门、奖励门、Boss 和主流程快照。位置使用独立不可靠有序通道，生成、选择、强化、伤害、死亡、复活、暂停和结算使用可靠事件。
- 本机餐车立即按同一移动规则预测，收到权威状态后校正；远端实体使用短插值缓冲。Boss 快照携带 `host_execution_time` 对齐预警表现，命中使用房主执行时刻的权威位置，不做回滚或射击式延迟补偿。
- 任意玩家可以请求全局暂停；暂停者或房主可以恢复。手动暂停、特殊三选一和复活计时均冻结；普通恢复不能越过特殊选择等待。

## 多人战斗

- 实现注记：食客、普通门、奖励门和 Boss 由场景内的 `MultiplayerSpawner` 按稳定生成载荷复制，节点上的 `MultiplayerSynchronizer` 只同步位置、活动状态和基础血量；Resource、随机结果、领取资格和统计仍通过稳定 ID 快照与可靠事件传输。客户端不再手动销毁这些权威对象，只等待房主 despawn，避免快照与场景复制的销毁竞态。玩家餐车按固定 P 槽位在各端建立并继续使用自定义位置预测/校正快照，投射物则以批量发射事件重放视觉，命中仍由房主裁决。个人统计按玩家拆包，新对象的稳定配置通过可靠事件只发送一次，避免四人局对象较多时单包超过 ENet MTU。固定种子、50/100ms 延迟和少量丢包只在命令行验收参数启用，正式启动默认关闭。
- 结算注记：胜利或失败事件前，房主按玩家可靠补发一次最终统计，客户端再写入个人战绩，避免最后一个不可靠统计包丢失造成记录落后。

- 开局人数为 `N` 时，普通食客、精英和 Boss 的最大/当前胃口均为单人基准的 `N` 倍；普通门、奖励门和每位玩家耐久不按人数缩放。
- 接触、远程和 Boss 伤害先将共享剩余胃口换算为单人基准（共享剩余胃口 ÷ `N`）。普通接触可同时命中所有重叠的存活玩家，每名玩家各承受一份完整基准伤害；远程每次随机锁定一名存活玩家；Boss 锁定主目标，范围预警可覆盖其他存活玩家。
- 普通门与奖励门在队伍中只有一套共享血量、稀有度和内容；所有玩家共同攻击，每位玩家拥有独立领取资格，任一玩家领取不消耗队友资格。普通门左右两侧仍可由不同玩家分别选择。
- 开局食材门为每位玩家显示自己的候选；特殊节点为每人独立三选一，所有在场玩家和幽灵选完后才继续；断线玩家从等待集合立即移除。
- 每位玩家独立拥有普通强化、特殊强化、食材、武器冷却、耐久、护盾和统计。强化变化由房主可靠广播，队友设备同步攻击表现和构筑状态。

## 幽灵与复活

- 耐久归零后进入幽灵：保留当前位置、移动、自动攻击和成长，输出统一乘 `0.01`；完全退出敌人锁定和伤害判定。幽灵餐车半透明但仍保留 P 色与标签。
- 幽灵可以领取奖励门；普通门只有对应侧公开基础血量已经清零时才可领取，不能免碰撞领取未击破普通门。
- 全队死亡档位从 `15s` 开始，每次实际倒下增加 `15s`，最高 `180s`；同一伤害事件倒下的玩家使用同一档位。若同一批伤害后没有存活玩家，立即失败，不进入复活等待。
- 复活先获得最终最大耐久的 `50%`，再应用幽灵期间按领取时上限缓存的维修实际点数；溢出维修转为临时护盾，并获得 `2s` 保护。幽灵期间餐车改造只增长最大耐久，维修只缓存，不提前复活或缩短倒计时。
- 单人局继续使用即时失败体验；唯一玩家归零即满足全员归零。

## 信息与记录

- 左上角按 P1～P4 竖排显示当前成员。每行使用固定色圆形 P 标识和彩色耐久数字，本机行增加轮廓；护盾以蓝色小号附值显示，幽灵行显示 `0` 与房主复活秒数。
- 底部耐久、烹饪圆环和暂停详情继续只展示本机数据；共享阶段、时间和结局由房主同步。
- 联机通关时所有仍连接的玩家（包括幽灵）在各自设备写入首胜解锁与个人战绩；记录补充房间 ID、P 位、开局人数、死亡次数、幽灵时间和网络模式。

## 验收边界

- 规则测试覆盖人数胃口倍率、单人基准伤害、多人重叠受击、幽灵目标排除、共享门血量与独立领取、死亡档位、180 秒封顶、幽灵输出、门领取限制、缓存维修、50%复活、溢出护盾和保护时间。
- 网络烟雾测试需以 1/2/4 个独立 Godot 进程验证创建、发现、手输 IP、锁房、暂停、断线、回房再开和固定种子；再注入 50/100ms 延迟与少量丢包验证无权威状态分叉。
- HUD 需在 `720×1280` 和 `405×720` 检查四行长耐久值、护盾、180 秒倒计时及现有顶部信息不重叠。Godot 运行和 Android 真机验收遵循项目批准与日志隔离规则。

## 本地编辑器验收入口

- 可复用场景为 `tests/network_acceptance_scene.tscn`，探针脚本为 `tests/network_acceptance_probe.gd`。房主等待 P1～P4 全部入房后自动开局，随后验证同批死亡、45 秒第二档、暂停/恢复、回房和房主断开通知。
- 启动探针时给每个进程传入 `--network-role=host|client`、`--network-index=1..3`、`--probe-dir=<项目/tmp下独立目录>`；固定种子使用 `--network-seed=<整数>`，扰动使用 `--net-delay-ms=50|100` 与 `--net-loss-percent=2`。需要验证完整时间轴时额外传入仅测试用的 `--network-smoke-test`，它会加速时间、自动选择三选一并在结算后回房；需要验证自动发现时客户端加 `--network-discovery-test`，发现端口被同机旧进程占用时双方可临时同时加 `--network-discovery-port=<1024以上端口>`；需要验证全灭优先级时使用 `--network-fail-test`；满员大厅测试由房主加 `--network-hold-lobby`，第五位客户端加 `--network-expect-join-rejection`；这些参数不要给正式游戏启动。
- 同机多开时，房主占用固定 UDP `28961`，其他进程会自动改用临时端口向房主查询；自动列表仍不可用时可在联机页手输房主 IPv4。游戏连接始终使用 ENet `28960`。
- 自动验收日志应同时看到四个进程相同的 `seed`、`count=4`、`ACCEPT_AFTER_BATCH_DAMAGE`、`ACCEPT_AFTER_SECOND_DAMAGE`、`PAUSE` 和 `RETURN_READY`；出现 `SCRIPT ERROR`、`Parser Error`、MTU 警告、槽位变化或任一进程状态不一致即判失败。
