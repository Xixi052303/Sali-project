# 美术生产与 AI 绘画流程

## 目标与状态

**章节状态：纸张艺术、AI 绘画生产方法与直接三维纸艺舞台已确认；用户指定的两张高完成度图片已取代三张简化图块，成为当前效果参考，正式可接入资产尚待制作。**

本流程用于在没有既有美术资产的阶段建立统一视觉基准，再逐步生产可以接入游戏的素材。首轮优先验证实机画面的信息可读性、纸层空间关系和资产可拆分性，不以一次性补齐完整内容量为目标。

## 已确认的生产原则

- 项目美术资产计划以 AI 绘画作为主要起稿与探索方式，后续根据游戏接入需要进行抠图、分层、修整和规格化处理。
- 每次生成都必须继承同一套项目风格规范，只替换本次需要表现的画面、资产或状态描述。
- 风格参考只用于限定纸张材质、复古印刷质感、半调网点、粗糙轮廓、错位强调色描边和纸层空间关系；不得照搬参考图的版式、角色、物件、标志或具体画面。
- 实机素材必须服从固定斜俯透视的 `9:16` 三维道路构图、六区玩法信息和移动端小尺寸可读性，不能为了纸艺纵深遮挡餐车、食客、料理、强化门或危险预警。
- UI 图片不烘焙实际文字和数值；AI 生成的伪文字、签名和水印不得进入正式资产。
- AI 生成结果不直接视为最终资产。只有通过统一视角、比例、轮廓、分层、透明边缘和游戏内可读性检查后，才能进入正式资源库。

## 单项生成流程

1. **确定任务**：写明资产的玩法职责、画面主体、状态、朝向、占位和输出用途。
2. **加载统一风格规范**：固定纸张材质、印刷语言、原创性限制与项目视觉边界。
3. **补充本次画面描述**：只替换当前要生成的场景或资产内容，不随意改动全局风格规则。
4. **生成候选**：在相同需求下生成若干候选，优先比较轮廓、信息层级和纸层关系，不因局部细节精美忽略玩法可读性。
5. **选定视觉锚点**：确定可继续使用的构图、视角、比例和材质表现，并记录进入项目风格板。
6. **整理游戏资产**：按用途完成抠图、补边、拆层、统一光向、尺寸、锚点和命名；需要动态表现的素材另行整理动作部件或帧序列。
7. **接入实机验证**：在目标手机画幅中检查遮挡、缩放、对比度、六区识别和高密度战斗可读性；未通过时返回对应环节修正。

## 本轮视觉母版

第一项美术任务是制作一张《小厨西》专用的 `9:16` 实机视觉母版，不先从孤立角色立绘或完整角色阵容开始。

母版至少同时呈现：

- 固定斜俯透视的纵向三维纸艺道路，以及可感知但不是硬车道的六个逻辑区域。
- 位于画面下部的纸艺餐车和通用厨师。
- 占据不同区域的普通食客。
- 土豆投射物、命中和食客逐渐吃饱的基础反馈。
- 左右各覆盖三个逻辑区域的普通强化门。
- 餐车耐久、食客胃口与危险预警的临时信息位置；实际文字和数值由 Godot 的 `Control` 或附着于物件的三维文字节点显示。
- 具有前、中、后景关系和实体厚度的纸层，但近景纸片、景深和阴影不得遮挡最高层级玩法信息。

母版验收重点：

1. 缩小到目标手机画幅后，玩家仍能立即找到餐车、主要食客和前方选择。
2. 食材、食客、强化门和危险预警在形状与颜色上能够相互区分。
3. 六个逻辑区域能够被感知，但画面不会误导玩家以为餐车会吸附车道中心。
4. 纸张厚度、阴影和层间纵深能够增强空间，而不会模糊实际占位与碰撞关系。
5. 角色保持荒诞温暖和夸张表现，不转为写实恐怖、档案照片复刻或与料理主题无关的信息图语言。
6. 选定画面能够进一步拆解为餐车、厨师、食客、道路、料理、强化门和界面装饰等独立资产方向。

### 当前效果参考

- 用户指定的两张高完成度图片取代原有三张简化图块，不再使用图块作为当前效果锚点。
- `reference-02-gameplay-master.png`作为实机效果主参考，限定纸偶角色、餐车、料理投射、强化门和Boss纸条信息共同出现时的完成度与层次关系；普通食客与普通门不沿用参考图的纸条血条布局。
- `reference-01-street-material.png`作为街景与材质参考，限定瓦楞纸断面、撕纸边缘、旧纸印刷颗粒、路边摊位和环境道具的丰富度。
- 两张图片只用于拆解媒介、材质、气质和完成度；其中的具体人物、商店、文字、标志、三条硬车道和界面布局不得直接照搬为本作规格。
- 正式母版继续遵守餐车与厨师、当前食客与危险、料理轨迹、前方强化门、街景装饰的读取顺序，并重新解决六区可感知但不形成吸附车道的问题。
- 参考图片、用途边界和实机复核项见[小厨西美术效果参考](../art/visual-masters/README.md)。

## 母版通过后的首批资产

首批资产只覆盖一段最小可玩流程：餐车前进与横移、自动投出土豆、满足或漏过普通食客、经过普通强化门并承受餐车耐久反馈。

| 类别 | 待制作内容 | 用途 |
| --- | --- | --- |
| 场景 | 一套道路地面、道路边缘、少量路边纸艺构件、六区辅助表现 | 验证纵向前进、占位和场景拼接 |
| 玩家主体 | 一辆餐车、一名通用厨师，以及正常、受击、无敌和失控的基础状态 | 建立操作主体与失败反馈 |
| 基础食材 | 土豆本体、飞行、命中与满足反馈 | 跑通首件教学食材 |
| 普通食客 | 一种普通食客及前进、进食、满足离场和投诉离场状态 | 验证胃口语义和漏客反馈 |
| 普通强化门 | 左右门体、选择反馈及首批功能图标占位 | 验证三区覆盖与即时成长选择 |
| 基础界面 | 餐车耐久、食客胃口、当前目标和危险预警的视觉框架 | 验证信息层级，不烘焙文字数值 |
| 反馈效果 | 料理命中、吃饱、餐车受击、投诉纸和修理的纸艺效果 | 区分满足、损伤与恢复 |

这一批通过实机验证后，再扩充法棍、生鸡蛋、蘑菇、胡萝卜、特殊强化、更多普通食客、精英、Boss和完整界面；身份、技能或阵容仍待定的内容不提前批量生产正式资产。

## 当前边界

- 本文不登记具体提示词；提示词属于生产执行材料，应根据确认后的风格板和资产任务生成。
- 本文不决定具体 AI 工具、模型、生成参数或版权审核流程。
- 实机采用可在编辑器预览的三维场景节点与竖立纸偶；本文仍不决定纸偶内部使用逐帧换图、分层骨骼还是节点动画。
- 本文不补造普通食客阵容、精英身份、Boss身份、食材进化或未确认的界面布局。

仍未确定的视觉与技术规格见[开放问题](open-questions.md#界面与视听表现)。
