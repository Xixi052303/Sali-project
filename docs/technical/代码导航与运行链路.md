# 代码导航与运行链路

## 启动与单局编排

- `scenes/run.tscn`仍是默认启动与 2D 对照场景，装配`RunController`、前进对象容器、餐车、武器、时间轴和HUD。
- `scenes/run_3d.tscn`是并行的直接 3D 竖切片入口；`RunController3D`使用与 2D 版相同的数据资源、`RunState`、时间轴与规则数值，但餐车、食客、门、投射物和 Boss 直接在`X/Z`道路平面运行。
- `Run3D`根节点使用统一`0.01`缩放规范编辑器世界尺寸；玩法数值仍保留原局部单位，跨容器位置统一换算回`Run3D`局部坐标，根缩放不参与规则调优。
- 3D 世界与动态对象分别由`world_background_3d.tscn`、`cart_3d.tscn`、`customer_3d.tscn`、`boss_3d.tscn`、`projectile_3d.tscn`和两类门场景装配；视觉节点可在编辑器预览，运行时通过`PackedScene`实例化，不由脚本临时搭建主要节点树。
- `scripts/run.gd`持有单局阶段、活动食客、强化门生成请求、目标选择与Boss切换。时间轴和普通波次只提交前进对象请求，`RunController`按请求顺序与纵向安全预测决定实际生成时机。
- `balance_tables/时间轴.xlsx`是当前竖切片事件和基准胃口曲线的运行主源；`TimelineExcelLoader`通过`ExcelReader47`严格校验并生成运行时`EncounterTimeline`，`data/timelines/vertical_slice.tres`仅在表格读取失败时回退。

## 数值表加载链

1. `RunController._ready()`在连接时间轴信号前调用`_load_timeline_balance()`。
2. `TimelineExcelLoader`校验工作表、结构标识、必填参数、事件时间顺序和事件ID。
3. 校验通过后建立运行时`EncounterTimeline`并交给`EncounterDirector`；重新进入单局会重新读取已保存的 Excel。
4. 文件缺失或校验失败时保留场景装配的`.tres`，并输出`BALANCE_TIMELINE_FALLBACK`。
5. Android 导出预设通过`balance_tables/*.xlsx`包含数值主表。

## 战斗与目标链路

1. `WeaponController`读取`RunState`中的全局倍率并从`RunController.get_priority_target()`取得最近有效目标。
2. 目标可以是食客、当前餐车半区内尚未满额的普通门面板、当前横向位置可取得的食客奖励门，或Boss；开局食材门不进入目标池。
3. `FoodProjectile`移动后调用`RunController.resolve_projectile_hits()`，依次结算食客、普通门、食客奖励门和Boss，并用目标实例记录防止重复命中。
4. 食客命中由`Customer.receive_satisfaction()`结算；门命中先消耗公开基础血量，清空后的后续命中才由`UpgradeGate`消耗隐藏升值血量并更新奖励百分位。
5. `Customer`与`Cart`以程序绘制主体的矩形范围判断实际撞车；相交时由`RunController`结算伤害与击败，成功绕开并离开屏幕底部时只清理实例。

## 强化与数值所有权

- `RunState`是局内强化的唯一可写状态。糖、快速备餐、酒、葱和淀粉使用全局乘算倍率；轻便餐车与坚固餐车使用固定点数加算；现场修理即时结算。
- `UpgradeData`保存普通门与食客奖励门的区间、实时百分位、实际值和稀有度；普通门的公开基础血量与隐藏升值血量由`UpgradeGate`持有，食客奖励门只持有隐藏升值血量。
- `CustomerData`保存食客相对基准胃口的倍率；普通食客生成时由`RunController`同时锁定奖励百分位、实例胃口与奖励数据，精英不参与该随机稀有度。
