# 代码导航与运行链路

## 启动与单局编排

- `scenes/run.tscn`是当前唯一主流程场景，装配`RunController`、前进对象容器、餐车、武器、时间轴和HUD。
- `scripts/run.gd`持有单局阶段、活动食客、强化门生成请求、目标选择与Boss切换。时间轴和普通波次只提交前进对象请求，`RunController`按请求顺序与纵向安全预测决定实际生成时机。
- `scripts/data/encounter_timeline.gd`与`data/timelines/vertical_slice.tres`提供当前竖切片事件时间和食客基准胃口曲线。

## 战斗与目标链路

1. `WeaponController`读取`RunState`中的全局倍率并从`RunController.get_priority_target()`取得最近有效目标。
2. 目标可以是食客、当前餐车半区内尚未满额的普通门面板，或Boss；开局食材门不进入目标池。
3. `FoodProjectile`移动后调用`RunController.resolve_projectile_hits()`，依次结算食客、普通门和Boss，并用目标实例记录防止重复命中。
4. 食客命中由`Customer.receive_satisfaction()`结算；门命中先消耗公开基础血量，清空后的后续命中才由`UpgradeGate`消耗隐藏升值血量并更新奖励百分位。
5. `Customer`与`Cart`以程序绘制主体的矩形范围判断实际撞车；相交时由`RunController`结算伤害与击败，成功绕开并离开屏幕底部时只清理实例。

## 强化与数值所有权

- `RunState`是局内强化的唯一可写状态。糖、快速备餐、酒、葱和淀粉使用全局乘算倍率；轻便餐车与坚固餐车使用固定点数加算；现场修理即时结算。
- `UpgradeData`保存固定掉落值，或保存普通门的区间、实时百分位、实际值和稀有度；门的公开基础血量与隐藏升值血量由`UpgradeGate`实例持有。
- `CustomerData`保存食客相对基准胃口的倍率；食客生成时由`RunController`计算并锁定实例胃口。
