# 代码导航与运行链路

## 启动与单局编排

- `scenes/run_3d.tscn`是唯一启动场景，装配`RunController3D`、3D前进对象容器、餐车、武器、时间轴和HUD；旧`run.tscn`与2D专用表现代码已移除。
- 餐车、食客、门、投射物和 Boss 直接在`X/Z`道路平面运行与判定，不存在不可见2D逻辑层或并行2D回归场景。
- `Run3D`及全部3D子场景根节点保持`Scale = 1`，运行位置、尺寸、速度和碰撞直接使用米制世界单位；设计像素只在触控输入和策划数据进入3D运行层时按`0.01`换算。
- 3D 世界与动态对象分别由`world_background_3d.tscn`、`cart_3d.tscn`、`customer_3d.tscn`、`boss_3d.tscn`、`projectile_3d.tscn`和两类门场景装配；视觉节点可在编辑器预览，运行时通过`PackedScene`实例化，不由脚本临时搭建主要节点树。
- `road_segment_3d.tscn`装配中央马路、左右路沿和左右人行道，路段总宽约`9.96m`、长度`12.8m`，路沿与人行道顶面高出马路`0.1m`；具体操作见[道路分层手调指南](道路分层手调指南.md)。
- `world_background_3d.tscn`实例化6个完整道路路段，其中从远方生成点到餐车前构成4段有效道路，另外2段负责滚动缓冲；固定相机和Mobile深度雾也在该场景中直接装配。`StreetProps`下每个`Sprite3D`直接保存图集`Region Rect`、米制尺寸和位置，具体操作见[街景面片手调指南](街景面片手调指南.md)。
- `scripts/run_3d.gd`持有单局阶段、活动食客、强化门生成请求、目标选择、开局已解锁食材池、四次特殊候选、Boss切换与胜后复跑。空的开局解锁配置按当前全部三种食材处理，餐车穿过随机开局门后才把所选食材加入`RunState`与武器控制器。`EncounterDirector`允许各时间轴事件按表现提前量独立触发；普通波次按各食客原速度计算提前量，生成请求保留原排程时刻的基准胃口。
- `scenes/hud.tscn`装配顶部阶段/时间、底部餐车耐久、临时提示、调试信息、选择与结算节点；`GameHud`只更新内容、安全区和动态候选按钮，旧常驻食材黑条已移除。
- `balance_tables/时间轴.xlsx`是当前竖切片事件和基准胃口曲线的运行主源；`TimelineExcelLoader`通过`ExcelReader47`严格校验并生成运行时`EncounterTimeline`，`data/timelines/vertical_slice.tres`仅在表格读取失败时回退。

## 数值表加载链

1. `RunController3D._ready()`在连接时间轴信号前调用`_load_timeline_balance()`。
2. `TimelineExcelLoader`校验工作表、结构标识、必填参数、事件时间顺序和事件ID。
3. 校验通过后建立运行时`EncounterTimeline`并交给`EncounterDirector`；重新进入单局会重新读取已保存的 Excel。
4. 文件缺失或校验失败时保留场景装配的`.tres`，并输出`BALANCE_TIMELINE_FALLBACK`。
5. Android 导出预设通过`balance_tables/*.xlsx`包含数值主表。

## 战斗与目标链路

1. `WeaponController3D`读取`RunState`中的全局倍率并从`RunController3D.get_priority_target()`取得`X/Z`玩法平面内距离餐车最近的有效目标；同距离时按横向距离与生成顺序稳定裁决。
2. 目标可以是食客、当前餐车半区内尚未满额的普通门面板、当前横向位置可取得的食客奖励门，或Boss；开局食材门不进入目标池。
3. `FoodProjectile3D`移动后调用`RunController3D.resolve_projectile_hits()`，依次结算食客、普通门、食客奖励门和Boss，并用目标实例记录防止重复命中；普通投射物使用上一位置到当前位置的连续线段避免高弹速穿透，横扫法棍追加道路平面扫路线段，蘑菇围绕餐车旋转并按弹速倍率持续向外扩张。
4. 食材寿命耗尽或越界且未耗尽命中次数时进入`0.2s`缩小淡出；命中耗尽仍立即回收。
5. 食客命中由`Customer3D.receive_satisfaction()`结算；门命中先消耗公开基础胃口，清空后的后续命中才由`UpgradeGate3D`消耗隐藏升值胃口并更新奖励百分位。
6. `Customer3D`与`Cart3D`在`X/Z`平面用主体矩形范围判断实际撞车；相交时由`RunController3D`结算伤害与击败，成功绕开并离开道路后方时只清理实例。普通食客结束时奖励门围绕其原位置双向小步避让，不再只向远端推移。
7. Boss战位按当前餐车纵坐标保持固定相对距离，避免编辑器调整餐车位置后让基础食材射程失效；直线与范围预警仍读取同一相对位置。

## 强化与数值所有权

- `RunState`是局内强化的唯一可写状态。糖、快速备餐、酒、葱和淀粉在各自属性内线性加算，快速备餐由累计攻速反推间隔；轻便餐车与餐车改造使用固定点数加算；紧急维修即时结算，溢出部分转为优先承伤且不会在单局中自动清除的临时护盾。
- `RunState`同时持有食材`Lv.1～Lv.3`、签名进化、逐食材满足贡献和特殊候选记录；食材自身等级倍率先计算，再与全局满足倍率相乘。
- `UpgradeData`保存普通门与食客奖励门的区间、实时百分位、实际值和稀有度；普通门的公开基础胃口与隐藏升值胃口由`UpgradeGate3D`持有，食客奖励门只持有隐藏升值胃口。
- `CustomerData`保存食客相对基准胃口的倍率；普通食客生成时由`RunController3D`同时锁定奖励百分位、实例胃口与奖励数据，精英不参与该随机稀有度。
- 单局结束或失败时，`RunController3D`把随机种子、四次候选与选择、食材等级/进化、逐食材贡献、三次精英和Boss耗时、耐久变化及Boss后复跑增量追加到`user://playtest_runs.jsonl`。`--run-seed=<整数>`用于复现同一随机序列。
