# 代码导航与运行链路

## 启动与单局编排

- `scenes/run_3d.tscn`是唯一启动场景，装配`RunController3D`、3D前进对象容器、餐车、武器、时间轴、HUD和仅调试构建可用的Debug菜单；旧`run.tscn`与2D专用表现代码已移除。
- `NetworkSession`（`scripts/network/network_session.gd`）是唯一网络 Autoload，负责 ENet `28960`、UDP 房间发现 `28961`（固定端口失败时使用临时端口查询回包）、版本/六本工作簿指纹握手、P1～P4 槽位、暂停、输入和房间回收；`PlayerRunContext` 为每个槽位保存独立`RunState`、餐车、武器、幽灵/复活与个人统计。
- 餐车、食客、门、投射物和 Boss 直接在`X/Z`道路平面运行与判定，不存在不可见2D逻辑层或并行2D回归场景。
- `Run3D`及全部3D子场景根节点保持`Scale = 1`，运行位置、尺寸、速度和碰撞直接使用米制世界单位；普通阶段横移输入与策划数据进入3D运行层时按`0.01`换算，Boss阶段二维拖动通过活动相机投影到道路平面。
- 3D 世界与动态对象分别由`world_background_3d.tscn`、`cart_3d.tscn`、`scenes/characters/customers/`下的四类独立食客场景、`scenes/characters/bosses/prototype_boss_3d.tscn`、`scenes/foods/`下的食材场景和两类门场景装配；`customer_base_3d.tscn`只保留共用行为与纸片回退结构。食材基础场景再包装现有模型，允许在编辑器单独调整朝向、中心和缩放；`cart_3d.tscn`同时保留可编辑的队友圆锥指针与 P 槽标签，运行时只写入槽位文字、颜色和本机隐藏状态，不把指针几何完全交给代码生成。运行时只实例化完整`PackedScene`，不直接把模型当作最终投射节点。Boss 身份仍按现行设计保持待定，不预先选择虎、鸦或鹿资产。
- `road_segment_3d.tscn`装配中央马路平面、左右竖直路沿面和左右人行道平面，路段可见总宽约`9.44m`、长度`12.8m`，人行道平面与路沿顶端位于`Y = 0.5m`；具体操作见[道路分层手调指南](道路分层手调指南.md)。
- `scenes/foods/base/`装配土豆、法棍、蘑菇、鸡蛋、胡萝卜和蛋液模型包装场景；`scenes/foods/projectiles/food_projectile_3d.tscn`负责共用投射物行为，`scenes/foods/derived/egg_puddle_3d.tscn`和`giant_baguette_3d.tscn`负责衍生攻击。所有食材场景沿既有`X/Z`运行层工作，不引入物理`Area3D`。
- `world_background_3d.tscn`实例化6个完整道路路段，其中从远方生成点到餐车前构成4段有效道路，另外2段负责滚动缓冲；固定相机和Mobile深度雾也在该场景中直接装配。`StreetProps`下每个`Sprite3D`直接保存图集`Region Rect`、米制尺寸和位置，具体操作见[街景面片手调指南](街景面片手调指南.md)。
- `scripts/run_3d.gd`持有单局阶段、活动食客、强化门与普通波次请求、目标选择、开局已解锁食材池、7次局内特殊候选、两场Boss和最终结算。空的开局解锁配置按当前全部五种食材处理；开局食材门在前进开始时立即触发，按当前最短首波间隔至少比首位普通食客早`2s`出现，餐车穿门后才把所选食材加入`RunState`与武器控制器。`EncounterDirector`按累计路程触发显式事件，普通门与波次各自按路程进度生成可复现请求，并由安全队列保持先后和间距。最终Boss结算通过`ProgressionStore`把首胜完成/内容解锁资格标记写入`user://progression.cfg`，暂不解锁具体内容。
- 联机时`RunController3D`由房主运行权威流程、随机、门/敌人/命中/耐久/死亡与结算；客户端只提交带序号的移动目标、暂停、特殊选择和离房请求。食客、普通门、奖励门和 Boss 由场景内`MultiplayerSpawner`负责生成/销毁，`MultiplayerSynchronizer`只传基础类型；Resource 不直接序列化，稳定 ID、基础数值、批量投射物发射事件和按对象拆分的 20Hz 世界快照由`NetworkSession`事件和`RunController3D`适配。玩家餐车按固定 P 槽位本地建立：房主按 ENet 半程 RTT 在相同速度与边界内前推客机餐车，本机仅在快照确认当前输入序号后预测校正，远端继续使用100ms样本插值。玩家快照中的当前耐久、耐久上限和护盾逐槽写回所有餐车头顶，本机槽位才可刷新底部耐久 HUD。
- `scenes/hud.tscn`装配顶部阶段/时间、底部餐车耐久、临时提示、调试信息、选择与结算节点；`GameHud`只更新内容、安全区和动态候选按钮，旧常驻食材黑条已移除。
- `scenes/debug_menu.tscn`由波浪键打开/关闭并在打开时暂停模拟；`DebugMenu`只发送测试动作和显示快照，食材、强化、生成、Boss与耐久等实际改动仍由`RunController3D`通过既有`RunState`和武器入口执行。Release构建不响应该菜单。
- `balance_tables/时间轴.xlsx`是路程事件、三段有效时间胃口曲线、独立总路程和普通门/波次数量的主源；目标有效时长与Boss目标时长只作策划校准参考。`战斗规则.xlsx`、`食客.xlsx`、`武器.xlsx`、`普通强化.xlsx`与`特殊强化.xlsx`分别是通用战斗参数、食客个体参数、食材基础参数、普通门与小份奖励共用候选池、特殊候选与等级规则主源。`TimelineExcelLoader`与`GameplayExcelLoader`共同复用`ExcelReader47`，只在单局内生成类型化运行数据，不改写共享资源。
- `scripts/network/multiplayer_rules.gd`集中保存人数胃口倍率、共享伤害换算、复活档位和幽灵输出的纯函数；`scripts/player_run_context.gd`保存死亡次数、幽灵时间和缓存维修，便于快照与战绩记录复用。

## 数值表加载链

1. `RunController3D._ready()`在建立`RunState`和候选池前依次读取时间轴、战斗规则、食客、武器、普通强化与特殊强化六本工作簿。
2. `TimelineExcelLoader`按Schema 4校验三段胃口结束时间、最大胃口、指数、独立总路程、事件路程顺序与事件ID；任一字段非法时整表回退。`GameplayExcelLoader`校验另外五本表的结构标识、枚举、数值边界、启用数量和重复ID。
3. 食客表按四个当前必需ID整体生成本局独立`CustomerData`，并把身份层级与行为类型分开；每个ID只映射到一个已在编辑器完整装配的食客场景。武器表生成本局独立`FoodData`；普通强化表生成`UpgradeData`区间模板；特殊强化表生成`SpecialUpgradeData`并配置`RunState`的食材最高等级与等级倍率。
4. 重新进入单局会重新读取已保存的 Excel；运行中不热替换，避免已生成对象和累计状态不一致。
5. 文件缺失或校验失败时，时间轴、食客与武器保留场景或`.tres`回退，战斗规则、普通强化与特殊强化使用脚本安全值，并输出对应`BALANCE_*_FALLBACK`；食客表不会部分替换。
6. Android 导出预设通过`balance_tables/*.xlsx`包含数值主表。

## 战斗与目标链路

1. `WeaponController3D`读取`RunState`中的全局倍率并从`RunController3D.get_priority_target_for_food()`取得当前食材的有效目标。法棍先过滤餐车正前方`60°`扇区（左右`30°`边界计入），再选择`X/Z`玩法平面内距离最近的目标；其他食材保持全平面最近目标规则。同距离时按横向距离与生成顺序稳定裁决。
2. 目标可以是食客、当前餐车半区内尚未满额的普通门面板、当前横向位置可取得的食客奖励门，或Boss；开局食材门不进入目标池。
3. `FoodProjectile3D`移动后调用`RunController3D.resolve_projectile_hits()`，依次结算食客、普通门、食客奖励门和Boss，并用目标实例记录防止重复命中；普通投射物使用上一位置到当前位置的连续线段避免高弹速穿透，巨型法棍使用横跨道路X轴且覆盖前后帧移动距离的矩形判定。`GiantBaguette3D`通过居中的独立旋转容器控制模型滚动，范围倍率同比放大法棍长宽高及巨型法棍横向判定；生成巨型法棍时由`WorldBackground3D.shake_camera()`触发相机轻震。蘑菇按`1/2/4/8…`圈驻留在`1/1.5/2/2.5…`倍基础半径，每档再用一圈向外增加`0.5`倍基础半径；蘑菇圆心始终取投射物所属 P 槽餐车，配置角速度只表示`1`倍半径处的基准，运行时按当前分段与呼吸后的实际半径反推角速度以保持切向线速度不变。酒提高该恒定线速度，淀粉只改变存续时间。
4. 食材寿命耗尽或越界且未耗尽命中次数时进入`0.2s`缩小淡出；命中耗尽仍立即回收。联机客户端重放投射物时继续执行同一套几何、去重、穿透与回收，仅在目标上播放命中特效，不修改胃口、门血和统计；实际数值仍只由房主结算，并通过可靠强化事件与 20Hz 快照校正。普通门和食客奖励门应用快照时都按权威隐藏升值胃口重建`UpgradeData`百分位、实际数值与稀有度表现；涉及耐久的点数文案使用房主生成时冻结并同步的耐久基准，避免各窗口按本机构筑显示不同数字。客户端不自行完成门领取、精英选择或结算。
5. 食客命中由`Customer3D.receive_satisfaction()`结算；门命中先消耗公开基础胃口，清空后的后续命中才由`UpgradeGate3D`消耗隐藏升值胃口并更新奖励百分位。
6. `Customer3D`与`Cart3D`在`X/Z`平面用主体矩形范围判断实际撞车；相交时由`RunController3D`结算伤害与解决结果，成功绕开并离开道路后方时只清理实例。普通食客与餐车未归零时的精英撞车都计为解决：普通食客留下奖励门，精英进入特殊三选一。普通食客结束时奖励门优先使用其原位置；仅与横向相交的食客或门做`4m`内双向小步避让，并允许约半个奖励门纵深的重合，等待队列中的位置锚点随道路同步前进。
7. Boss战位按当前餐车纵坐标保持固定相对距离；`RunController3D`在开战与胜利时切换`Cart3D`的Boss移动模式，指针投影到道路平面后使用原横移速度进行二维移动，纵向范围限制在开战站位与Boss主体后方之间，结束时恢复开战站位。`PrototypeBoss3D`在攻击开始时锁定餐车坐标并放置`LineAttackAnchor`或`AreaAttackAnchor`，可见预警与命中都使用对应的`X/Z`二维区域；轨迹节点的局部动作由场景`AnimationPlayer`维护。中途Boss胜利进入特殊三选一，最终Boss胜利直接结算并写入首胜完成标记。

### 鸡蛋与胡萝卜专项链路

- `RunController3D.resolve_projectile_hits()`、`resolve_gate_projectile_hit()`和`resolve_reward_projectile_hit()`把鸡蛋命中统一转为`FoodPuddle3D`；蛋液的`egg_puddle`衍生攻击数据来自武器表“衍生攻击”行，只独立维护基础间隔、持续倍率和满足倍率，其他基础属性与强化倍率由加载器复制鸡蛋主行。房主生成蛋液时先对命中目标结算首跳，再由`resolve_puddle_hits()`按目标实例分别维护周期，同时可靠广播一次蛋液生成载荷；客户端只恢复位置、范围、持续时间和所属 P 槽的表现实例，不重复伤害。普通门与奖励门也通过各自的蛋液适配入口处理，开局食材门仍不可攻击。
- `FoodPuddle3D`只做圆形`X/Z`接触扫描，不使用物理`Area3D`；前进阶段按道路滚动，Boss阶段保持世界位置，离开后清除该目标的周期状态，重新进入立即结算，多个实例互不共享计时。
- `FoodProjectile3D`的`CARROT_SWEEP`类型把胡萝卜本体锚定在投射物所属 P 槽餐车前方工作点的固定半径弧线上，从左侧`90°`顺时针扫到右侧`90°`；基础类型在首个端点固定位置，延长的剩余持续时间只让`Model`子节点绕自身本地长轴自转，`carrot_bounce`进化才在端点反向并清空本单程去重集合。视觉模型与`carrot_3d.tscn`中的`DamageHitbox`共同以该工作点原点为轴心作为长棒旋转，运行时读取盒形轮廓做整根`X/Z`判定；初始模型尺寸来自场景编辑器，范围强化只在场景基准上等比扩大模型与轮廓，武器表的环绕角速度在发射时按扫掠半径换算为切向线速度。

## 强化与数值所有权

- `RunState`是局内强化的唯一可写状态。糖、快速备餐、酒、葱和淀粉在各自属性内线性加算，快速备餐由累计攻速反推间隔；轻便餐车使用固定设计点数累计后经对数曲线转译，餐车改造按结算时当前耐久上限的`2%～11%`复利提高上限并同步补充当前耐久；紧急维修即时结算，溢出部分转为优先承伤且不会在单局中自动清除的临时护盾。
- `RunState`同时持有食材等级、签名进化、逐食材满足贡献和特殊候选记录；最高等级与自身等级倍率由`特殊强化.xlsx`配置，食材自身等级倍率先计算，再与全局满足倍率相乘。
- `UpgradeData`保存普通门与食客奖励门的区间、实时百分位、实际值、稀有度和 Excel 门牌文案模板；普通门、食客奖励门及领取提示共用模板解析结果。普通门的公开基础胃口与隐藏升值胃口由`UpgradeGate3D`持有，食客奖励门只持有隐藏升值胃口。
- `CustomerData`分别保存身份层级与单一行为，并保存相对基准胃口的倍率、移动速度、占位、攻击参数及完整食客场景引用；普通食客生成时由`RunController3D`同时锁定奖励百分位、实例胃口与奖励数据，精英不参与该随机稀有度。
- 单局结束或失败时，`RunController3D`把随机种子、结局与有效时长、7次局内特殊候选/选择、食材等级与进化、普通强化汇总、逐食材贡献、六次精英与两场Boss耗时、门/食客计数、耐久与护盾汇总及最终Boss首胜标记追加到`user://playtest_runs.jsonl`。`--run-seed=<整数>`用于复现同一随机序列。记录结构暂时仍保留`post_boss_performance`旧字段，但当前流程没有Boss后复跑阶段，不应把该字段解释为独立阶段数据。

```powershell
Godot_v4.7-stable_win64_console.exe --headless --path . --script res://tests/test_core.gd

```
