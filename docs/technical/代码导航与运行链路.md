# 代码导航与运行链路

## 启动与单局编排

- `scenes/run_3d.tscn`是唯一启动场景，装配`RunController3D`、3D前进对象容器、餐车、武器、时间轴、HUD和仅调试构建可用的Debug菜单；旧`run.tscn`与2D专用表现代码已移除。
- 餐车、食客、门、投射物和 Boss 直接在`X/Z`道路平面运行与判定，不存在不可见2D逻辑层或并行2D回归场景。
- `Run3D`及全部3D子场景根节点保持`Scale = 1`，运行位置、尺寸、速度和碰撞直接使用米制世界单位；普通阶段横移输入与策划数据进入3D运行层时按`0.01`换算，Boss阶段二维拖动通过活动相机投影到道路平面。
- 3D 世界与动态对象分别由`world_background_3d.tscn`、`cart_3d.tscn`、`scenes/characters/customers/`下的四类独立食客场景、`scenes/characters/bosses/prototype_boss_3d.tscn`、`projectile_3d.tscn`和两类门场景装配；`customer_base_3d.tscn`只保留共用行为与纸片回退结构。小鼠、狐狸、青蛙、六席精英和当前 Boss 占位视觉的模型、形状与接触阴影都常驻在对应场景中，可在编辑器直接预览和修改；运行时只实例化完整`PackedScene`，不再向`ModelRoot`临时添加模型或覆盖阴影尺寸。Boss 身份仍按现行设计保持待定，不预先选择虎、鸦或鹿资产。
- `road_segment_3d.tscn`装配中央马路、左右路沿和左右人行道，路段总宽约`9.96m`、长度`12.8m`，路沿与人行道顶面高出马路`0.1m`；具体操作见[道路分层手调指南](道路分层手调指南.md)。
- `world_background_3d.tscn`实例化6个完整道路路段，其中从远方生成点到餐车前构成4段有效道路，另外2段负责滚动缓冲；固定相机和Mobile深度雾也在该场景中直接装配。`StreetProps`下每个`Sprite3D`直接保存图集`Region Rect`、米制尺寸和位置，具体操作见[街景面片手调指南](街景面片手调指南.md)。
- `scripts/run_3d.gd`持有单局阶段、活动食客、强化门生成请求、目标选择、开局已解锁食材池、四次特殊候选、Boss切换与胜后复跑。空的开局解锁配置按当前全部三种食材处理，餐车穿过随机开局门后才把所选食材加入`RunState`与武器控制器。`EncounterDirector`允许各时间轴事件按表现提前量独立触发；普通波次按各食客原速度计算提前量，生成请求保留原排程时刻的基准胃口。
- `scenes/hud.tscn`装配顶部阶段/时间、底部餐车耐久、临时提示、调试信息、选择与结算节点；`GameHud`只更新内容、安全区和动态候选按钮，旧常驻食材黑条已移除。
- `scenes/debug_menu.tscn`由波浪键打开/关闭并在打开时暂停模拟；`DebugMenu`只发送测试动作和显示快照，食材、强化、生成、Boss与耐久等实际改动仍由`RunController3D`通过既有`RunState`和武器入口执行。Release构建不响应该菜单。
- `balance_tables/时间轴.xlsx`是事件、两段基准胃口曲线和普通波次起止/阶段间隔的主源；`食客.xlsx`、`武器.xlsx`、`普通强化.xlsx`与`特殊强化.xlsx`分别是食客个体参数、食材基础参数、两类普通强化池和特殊候选/等级规则主源。`TimelineExcelLoader`与`GameplayExcelLoader`共同复用`ExcelReader47`，只在单局内生成类型化运行数据，不改写共享资源。

## 数值表加载链

1. `RunController3D._ready()`在建立`RunState`和候选池前依次读取时间轴、食客、武器、普通强化与特殊强化工作簿。
2. `TimelineExcelLoader`按Schema 2校验时间轴结构、两段胃口时间顺序、普通波次阈值/正数间隔、事件顺序与事件ID；任一字段非法时整表回退。`GameplayExcelLoader`校验另外四本表的结构标识、枚举、数值边界、启用数量和重复ID。
3. 食客表按四个当前必需ID整体生成本局独立`CustomerData`，并把身份层级与行为类型分开；每个ID只映射到一个已在编辑器完整装配的食客场景。武器表生成本局独立`FoodData`；普通强化表生成`UpgradeData`区间模板；特殊强化表生成`SpecialUpgradeData`并配置`RunState`的食材最高等级与等级倍率。
4. 重新进入单局会重新读取已保存的 Excel；运行中不热替换，避免已生成对象和累计状态不一致。
5. 文件缺失或校验失败时，时间轴、食客与武器保留场景`.tres`，普通/特殊强化使用脚本安全回退，并输出对应`BALANCE_*_FALLBACK`；食客表不会部分替换。
6. Android 导出预设通过`balance_tables/*.xlsx`包含数值主表。

## 战斗与目标链路

1. `WeaponController3D`读取`RunState`中的全局倍率并从`RunController3D.get_priority_target_for_food()`取得当前食材的有效目标。法棍先过滤餐车正前方`90°`扇区（左右`45°`边界计入），再选择`X/Z`玩法平面内距离最近的目标；其他食材保持全平面最近目标规则。同距离时按横向距离与生成顺序稳定裁决。
2. 目标可以是食客、当前餐车半区内尚未满额的普通门面板、当前横向位置可取得的食客奖励门，或Boss；开局食材门不进入目标池。
3. `FoodProjectile3D`移动后调用`RunController3D.resolve_projectile_hits()`，依次结算食客、普通门、食客奖励门和Boss，并用目标实例记录防止重复命中；普通投射物使用上一位置到当前位置的连续线段避免高弹速穿透，巨型法棍使用横跨道路X轴且覆盖前后帧移动距离的矩形判定。`GiantBaguette3D`通过居中的独立旋转容器控制模型滚动，范围倍率同比放大法棍长宽高及巨型法棍横向判定；生成巨型法棍时由`WorldBackground3D.shake_camera()`触发相机轻震。蘑菇每档先按当前半径旋转一圈，再用下一圈平滑扩到当前半径的`1.5`倍；酒只改变转速，淀粉只改变存续时间。
4. 食材寿命耗尽或越界且未耗尽命中次数时进入`0.2s`缩小淡出；命中耗尽仍立即回收。
5. 食客命中由`Customer3D.receive_satisfaction()`结算；门命中先消耗公开基础胃口，清空后的后续命中才由`UpgradeGate3D`消耗隐藏升值胃口并更新奖励百分位。
6. `Customer3D`与`Cart3D`在`X/Z`平面用主体矩形范围判断实际撞车；相交时由`RunController3D`结算伤害与击败，成功绕开并离开道路后方时只清理实例。普通食客结束时奖励门优先使用其原位置；仅与横向相交的食客或门做`4m`内双向小步避让，并允许约半个奖励门纵深的重合，等待队列中的位置锚点随道路同步前进。
7. Boss战位按当前餐车纵坐标保持固定相对距离；`RunController3D`在开战与胜利时切换`Cart3D`的Boss移动模式，指针投影到道路平面后使用原横移速度进行二维移动，纵向范围限制在开战站位与Boss主体后方之间，结束时恢复开战站位。`PrototypeBoss3D`在攻击开始时锁定餐车坐标并放置`LineAttackAnchor`或`AreaAttackAnchor`，其下轨迹节点的局部动作由场景`AnimationPlayer`维护，因此代码生成位置与手调动画互不争用属性。

## 强化与数值所有权

- `RunState`是局内强化的唯一可写状态。糖、快速备餐、酒、葱和淀粉在各自属性内线性加算，快速备餐由累计攻速反推间隔；轻便餐车与餐车改造使用固定点数加算；紧急维修即时结算，溢出部分转为优先承伤且不会在单局中自动清除的临时护盾。
- `RunState`同时持有食材等级、签名进化、逐食材满足贡献和特殊候选记录；最高等级与自身等级倍率由`特殊强化.xlsx`配置，食材自身等级倍率先计算，再与全局满足倍率相乘。
- `UpgradeData`保存普通门与食客奖励门的区间、实时百分位、实际值、稀有度和 Excel 门牌文案模板；普通门、食客奖励门及领取提示共用模板解析结果。普通门的公开基础胃口与隐藏升值胃口由`UpgradeGate3D`持有，食客奖励门只持有隐藏升值胃口。
- `CustomerData`分别保存身份层级与单一行为，并保存相对基准胃口的倍率、移动速度、占位、攻击参数及完整食客场景引用；普通食客生成时由`RunController3D`同时锁定奖励百分位、实例胃口与奖励数据，精英不参与该随机稀有度。
- 单局结束或失败时，`RunController3D`把随机种子、四次候选与选择、食材等级/进化、逐食材贡献、三次精英和Boss耗时、耐久变化及Boss后复跑增量追加到`user://playtest_runs.jsonl`。`--run-seed=<整数>`用于复现同一随机序列。
