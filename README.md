# 小厨西

Godot 4.7 制作的竖屏移动端直接 3D 纸艺玩法竖切片。当前使用可在编辑器预览的临时纸艺节点，不代表正式美术或声音质量。

## 运行

1. 使用 Godot 4.7 打开项目。
2. 运行主场景 `scenes/run_3d.tscn`。
3. 普通阶段按住鼠标或单指横向拖动餐车；Boss阶段可向任意方向拖动，但不能越过Boss。松开后餐车保持当前位置。

`scenes/run_3d.tscn`是项目唯一启动入口；旧 2D 场景已退役并移除。3D 相机、道路、灯光、纸偶、标签和预警均以可编辑场景节点装配。

全部3D场景根节点保持`Scale = 1`并直接使用米制坐标；策划数据与普通阶段横移输入保留设计像素，只在运行边界按`1像素 = 0.01米`换算；Boss阶段的二维拖动由相机投影到道路平面。背景子场景单独打开时与主场景中的比例一致。

内部设计分辨率为 `720 × 1280`，桌面调试窗口默认为 `405 × 720`，移动端锁定竖屏。

## 当前可玩内容

- 约8分钟的正式流程骨架：50道普通强化门、250个普通波次（按当前每四波一次双客约312只普通食客）、6次精英遭遇和2场Boss。六只精英与中途Boss共提供7次局内特殊三选一，最终Boss胜利后直接结算并记录首胜完成状态。
- 固定相机可同时看到从远方生成点到餐车前的四段有效道路；额外路块只用于循环缓冲。
- 每段道路由中央马路、左右竖直路沿面和左右人行道五个独立3D节点组成；人行道平面与路沿顶端当前位于`Y = 0.5m`，整段可见宽度约`9.44m`。
- 50道普通强化门按累计路程分布；Boss与选择阶段暂停前进，不继续生成普通门和普通食客。
- 普通强化门每侧基础血量为`(1+初始百分位)×基准胃口`，高稀有门拥有更高撞门风险；击破后继续攻击可提高奖励，隐藏升值血量不显示。
- 普通食客只显示当前胃口数字，数字使用对应奖励稀有度色；普通门每侧只显示公开基础胃口数字，数字同样使用该侧当前奖励稀有度色，食客奖励门不显示升值胃口。普通门与食客奖励门会随实时稀有度跨档立即改变门板颜色，纸条血条只用于Boss。
- 撞门会按所选侧剩余基础血量损失餐车耐久，但仍只取得该侧效果，中心点不会同时取得两侧奖励。
- 八类普通强化使用独立原型区间；同类持久百分比强化线性加算，并显示本次与累计效果。
- `餐车改造`提高耐久上限并同步补充耐久；`紧急维修`按耐久上限恢复，溢出点数转为优先承伤的局内临时护盾。
- 土豆固定竖直发射且不会改变角度；取得“瞄准投喂”后才会在存在目标时按目标方向发射，没有目标时仍持续朝前攻击。
- 法棍直线穿透攻击，范围增长会同比放大模型长宽高；取得“巨型法棍”后每3秒额外发射一根基础横跨四格、绕自身中心滚动直行且不追踪的巨型法棍，并在发射时轻微震屏。
- 蘑菇以恒定切向速度环绕餐车，半径逐档增加`0.5`倍基础半径，各档驻留圈数按`1/2/4/8…`翻倍且外扩各占一圈；取得“呼吸菌圈”后，会在当前分段半径的一至两倍之间周期扩缩，并按实际半径同步放慢或加快旋转。
- 鸡蛋基础数值对标土豆；命中后不直接扣除目标数值，而是在命中位置留下独立蛋液，首跳立即结算，视觉从小尺寸快速放大，接触目标后每`0.5s`结算一次，离开重入立即结算，多个蛋液可以叠加。
- 胡萝卜基础数值对标土豆，默认命中目标数为`999`；胡萝卜以餐车前方工作点为0点，拿一根保持比例的大棒从左侧`90°`顺时针扫到右侧`90°`，整根盒形轮廓参与命中，端点立即反向，弹速影响扫掠移速，持续强化增加往返次数。模型与伤害轮廓均可在`scenes/foods/base/carrot_3d.tscn`中调整。
- 所有普通投射物初始均不会在飞行中追踪目标。按当前武器运行值，土豆与法棍的基础飞行距离约为`0.72`屏与`0.78`屏；弹速和持续时间强化都会扩大实际射程，实时射程与不计穿透的理论DPS见`武器.xlsx`预览图。
- 当前有三类普通食客和一种横跨六区的精英模板；普通食客随机抽取奖励类型与稀有度，并按同一百分位提高生成胃口。精英每局出现6次，按当时基准胃口的`1.5`倍生成；非致命撞车同样算解决并进入特殊三选一。
- 食客可以在画面上方提前存在并被攻击，普通门、食客和食客奖励门会按安全距离错开生成。
- 普通食客使用密集波次；只有与餐车主体实际相撞才会损伤耐久，成功绕开并从屏幕底部离场不会造成伤害或掉落。
- 普通食客被满足或撞击击败后，会在原占位留下同宽度、无基础血量且可攻击升值的奖励门；餐车必须经过对应区域才能领取，错过后不会自动吸取。
- 普通食客头顶只显示稀有度色的当前胃口数字；Boss使用独立纸条血条与阶段信息，正式纸艺样式仍待资产替换。
- 特殊三选一使用五食材十项候选池：土豆、法棍、蘑菇、鸡蛋和胡萝卜食材/等级卡，三项既有进化、全局加量和全局穿透`+1`的酱油。每次完全随机抽取三个不同有效候选，不设软保底；鸡蛋和胡萝卜暂不新增专属进化。
- 食材首次取得为`Lv.1`，重复取得最高升至`Lv.3`；每级自身满足倍率为`×2.25`，再与普通强化的全局满足倍率相乘。
- 两场Boss遭遇当前复用一名拥有直线与范围预警的原型Boss，均按登场时基准胃口的`3`倍生成；战斗期间餐车可在开战站位与Boss之间前后左右移动，二维合速度与普通横移一致。两类攻击按可见预警的`X/Z`范围结算，轨迹由Boss场景中的`AnimationPlayer`维护，动态目标锚点仍由代码放置。
- 餐车耐久、0.5秒受击无敌、结算统计和一键重开。
- 最终Boss首胜会把完成/后续内容解锁资格标记保存到`user://progression.cfg`；具体解锁内容树尚未接入，当前五种食材仍默认全部解锁。
- 餐车耐久固定在屏幕底部靠近厨师视觉焦点；不再常驻显示黑色食材栏。
- 固定HUD结构位于`scenes/hud.tscn`，可在编辑器中直接预览和调整；只有特殊三选一的候选按钮按运行内容动态填充。
- 固定相机使用近宽远窄的斜俯透视，远端生成区由Mobile深度雾遮蔽；道路延长不改变食客与门的原接近速度。
- 未命中的食材会在`0.2s`内快速缩小淡出；食客奖励门优先保留在食客原位置附近。
- 720×1280、19.5:9和20:9竖屏适配结构。

策划案中尚未确认的概率、区间和正式角色内容仍然是原型值。当前时间轴、战斗规则、食客、武器、
普通强化和特殊强化分别以`balance_tables/`中的同名工作簿为运行主源；场景装配的食客、
食材资源与脚本默认值保留为读取失败时的安全回退。
投射物只在发射瞬间确定方向；数据层已预留按食材开启追踪的特殊强化接口。
每局会输出随机种子，并将结局、有效时长、食材等级与进化、特殊选择、普通强化汇总、逐食材满足贡献、门与食客计数、精英/Boss耗时及耐久/护盾汇总写入本地测试记录。可使用`--run-seed=<整数>`复现候选与生成随机序列。

## 数值表

时间轴、战斗规则、食客、武器、普通强化和特殊强化可以直接在`balance_tables/`的对应小表中修改。
保存并关闭工作簿后重新开始本局或重新运行`run_3d.tscn`，游戏会读取最新保存值；运行中的
既有单局不会热替换，以免已生成对象、候选池和累计状态前后不一致。

`balance_tables/archive/小厨西_旧切片数值快照_2026-07-27.xlsx`只保存旧切片历史，不参与运行，也不作为当前数值参考。

## 街景手动调整

街景裁剪、大小、位置和新增面片的编辑步骤见[街景面片手调指南](docs/technical/街景面片手调指南.md)。所有街景节点都位于`world_background_3d.tscn/StreetProps`下。

道路五层的贴图、宽度和高度调整见[道路分层手调指南](docs/technical/道路分层手调指南.md)。六个循环路段统一实例化`road_segment_3d.tscn`。

成功读取时输出对应的`BALANCE_*_LOADED`。表格缺失或校验失败时输出对应的
`BALANCE_*_FALLBACK`，并使用场景装配资源或脚本默认值作为安全回退。

## 自动校验

核心规则测试：

```powershell
Godot_v4.7-stable_win64_console.exe --headless --path . --script res://tests/test_core.gd
```

Excel 数值链专项测试：

```powershell
Godot_v4.7-stable_win64_console.exe --headless --path . --script res://tests/test_balance_excel.gd
```

完整流程烟雾测试：

```powershell
Godot_v4.7-stable_win64_console.exe --headless --fixed-fps 60 --path . --quit-after 4000 -- --smoke-test
```

成功时分别输出`CORE_TESTS_OK`、`BALANCE_EXCEL_TEST_OK`与`SMOKE_TEST_OK`。

## 目录

- `scenes/`：可运行场景。
- `scripts/`：单局、单位、武器、界面和数据类型。
- `balance_tables/`：六本运行数值主表与只读历史快照。
- `addons/excel_reader_47/`：可跨项目复制的 Godot 4.7 `.xlsx`读取器。
- `data/`：食材、食客、Boss及时间轴安全回退资源。
- `docs/`：玩法策划案。
- `tests/`：无需第三方插件的核心规则测试。
